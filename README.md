# AMR Story Pipeline

A small, local database for finding antimicrobial resistance (AMR) therapeutic stories worth writing about: new trials, preclinical programmes and the organisations behind them, with deliberate attention to developers outside North America and Europe.

It pulls candidates from free public sources into one SQLite file, logs every new trial and every phase or status change, and puts candidates on a scoring board where a human scores them on a 16-point rubric and decides what to write.

**Status:** in testing on real data since November 2026.

## How this was built

I set the goal and scope, chose the sources, and made the scope decisions (which regions and organisation types reach the board, what is out of scope). The code was written by Claude, an AI coding assistant, and tested by it before delivery; I ran every script on my own machine and reported failures back. As a microbiologist, the workflows are built around running files rather than writing code.

The pipeline itself contains no AI. Selection is rule-based (keyword filters and registry rules), and scoring is done by hand.

## Why it exists

The usual sources for AMR innovation lean heavily Western:

ClinicalTrials.gov mostly captures non-US trials when sponsors need the FDA or a journal; many domestic trials in China, India and Japan are registered only nationally.

This project adds national registries (through the WHO trial registry platform) and regional start-up lists, and flags candidates from underreported regions so they are not lost in the ranking.

## Data sources

| Source | What it contributes | Loaded by |
| --- | --- | --- |
| [ClinicalTrials.gov via AACT](https://aact.ctti-clinicaltrials.org/) | Interventional drug and biological trials whose condition mentions resistance | `ingest.py` + `aact_query.sql` |
| [WHO ICTRP](https://trialsearch.who.int/) | Trials from national registries (ChiCTR, CTRI, jRCT, CRIS, PACTR, ReBEC and others), from your own XML or CSV export | `ingest_ictrp.py` |
| CARB-X portfolio | 30 therapeutic developers | `seed_entities.sql` |
| WHO 2025 antibacterial pipeline reviews (preclinical and clinical) | Developers, products, and the trial IDs WHO cites | SQL file generated by `make_step3_sql.py` |
| C-CAMP AMR start-up list (India) | Indian therapeutic start-ups | Same generated file |

No data is included in this repository. You download each source yourself, under its own terms.

## Files

| File | Language | What it does | When to run it |
| --- | --- | --- | --- |
| `schema.sql` | SQLite | Creates the original six tables | Once, first |
| `migrate_v2.sql` | SQLite | Adds `sponsor_name` to old databases | Only if your database predates that column |
| `migrate_v3.sql` | SQLite | Adds registries, regions, a papers table and the scoring board | Once, after `schema.sql` |
| `migrate_v4.sql` | SQLite | Adds 'irrelevant' as a decision, for false positives that never deserved scoring | Once, after `migrate_v3.sql` |
| `check_database.sql` | SQLite | Lists any missing column, with a ready-made fix | After any upgrade |
| `seed_entities.sql` | SQLite | Enters 30 CARB-X developers | Once (not safe to re-run) |
| `aact_query.sql` | PostgreSQL | The ClinicalTrials.gov search, run on the AACT server | Read by `ingest.py` |
| `ingest.py` | Python | Imports and updates ClinicalTrials.gov trials | Weekly |
| `ingest_ictrp.py` | Python | Imports a WHO ICTRP export; skips ClinicalTrials.gov records and links duplicates | Weekly |
| `make_step3_sql.py` | Python | Turns the WHO pipeline spreadsheets and C-CAMP list into one SQL import file | Once per WHO edition |
| `refresh_board.sql` | SQLite | Adds new candidates to the scoring board without touching existing scores | Weekly, after imports |
| `score.py` | Python | Scores candidates one at a time in the terminal, showing the rubric beside each question | Whenever you score |
| `match_sponsors.sql` | SQLite | Lists trial sponsors that resemble known organisations, for manual linking | When curating |

## Getting started

You need [DB Browser for SQLite](https://sqlitebrowser.org/) and Python 3. Keep every file and `amr_pipeline.db` in one folder.

1. In DB Browser, create a new database called `amr_pipeline.db`. In **Execute SQL**, run `schema.sql`, then `migrate_v3.sql`, then `migrate_v4.sql`, then `seed_entities.sql`, clicking **Write Changes** after each.
2. Run `check_database.sql`. An empty result means the database is complete.
3. For ClinicalTrials.gov: register for a free [AACT account](https://aact.ctti-clinicaltrials.org/), run `pip install psycopg2-binary`, set `AACT_USER` and `AACT_PASSWORD` as environment variables, then run `python ingest.py`.
4. For national registries: search [trialsearch.who.int](https://trialsearch.who.int/), export the results as XML, save the file as `ictrp_<date>.xml` in the folder, then run `python ingest_ictrp.py`.
5. Run `refresh_board.sql`, then `python score.py` to score candidates one at a time, and open the `scoring_board` view to see them ranked.

Credentials are read from environment variables and never stored in any file.

## The scoring board

`story_candidates` holds one row per possible story in one of three phases (preclinical startup, clinical trial, academic finding). Eight criteria are scored 0 to 2 (two of them 0 or 2), giving a total out of 16; disallowed values are refused by the database. A separate `underreported_region` flag marks candidates from regions listed in `refresh_board.sql`. It is kept out of the total on purpose: it is a filter for finding stories, not a measure of merit.

## Known limitations

- Coverage is wider, not complete. The WHO preclinical list itself is 94% high-income-country products, China's drug regulator trial platform has to be checked by hand, and academic papers are not collected yet.
- The AACT keyword filter is blunt: it admits non-AMR conditions such as treatment-resistant depression and misses AMR trials that never mention resistance.
- Duplicate detection depends on registries citing each other's trial IDs.
- Organisation types for WHO-listed developers are inferred from company size, not verified one by one.
- Registry data are entered by sponsors and are not independently validated.

## Data terms

If you publish from this pipeline, credit the sources: ClinicalTrials.gov via AACT (CTTI), and "WHO ICTRP" together with the date the data were processed. WHO asks that ICTRP data not be used for marketing or commercial purposes. Check each source's current terms before publishing.
